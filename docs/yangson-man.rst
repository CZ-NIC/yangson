.. _yangson-man:

-------------------
Yangson manual page
-------------------

.. program:: yangson

Synopsis
========

:program:`yangson` <model> [<options>] <command> [<args>]

:program:`yangson` -V | -h

Description
===========

This program makes selected high-level functions of the Yangson
library available as commands for use from the command line.

All commands require a complete YANG data model that can be passed to
the program in one of the following forms:

* a textual data model specification in JSON representation conforming to the
  original YANG library format of [RFC7895]_, or
* a serialized (pickled) data model object in the binary format of
  Python's `pickle <https://docs.python.org/3/library/pickle.html>`_
  module. The pickled data model can also be generated by this program
  and saved to a file.

This program is not intended for debugging YANG modules. Errors in
YANG modules usually lead to uncaught Python exceptions.

Version and Help
================

.. option:: -V, --version

   Print the installed version of Yangson library and exit.

.. option:: -h, --help

   Print an overview of the syntax and exit.

Data Model and Options
======================

.. option:: <model>

   Name of the file containing either YANG library data in JSON format
   or pickled data model object.

.. option:: -P, --pickled

   This option indicates that *<model>* contents is to be interpreted
   as a serialized (pickled) data model object. See also
   :ref:`dump-cmd` command.

.. option:: -p <module_path>, --path <module_path>

   This option specifies a list of directories to search for YANG
   modules. It is only applicable if the :option:`--pickled` option is
   **not** used.  The *<module_path>* argument is a colon-separated list
   of directory names. By default, the value of the YANG_MODPATH
   environment variable is used if it is set, otherwise the
   module path contains only the current directory.

   All YANG modules specified in the YANG library need to be located in
   one of these directories, and their file names have to be in the
   following form:

   .. code-block:: none

      module-or-submodule-name ['@' revision-date] '.yang'

.. option:: -S <subschema>, --subschema <subschema>

   Use only a subtree of the schema that corresponds to an action, RPC or
   notification. The *<subschema>* argument is a :term:`schema path`
   pointing to the root of the selected subschema.

Commands
========

Each command selects an operation on the data model and possibly
instance data. If no command is specified, the program just builds
the data model and exits silently if no errors are found.

.. option:: -h, --help

   This option is accepted by all commands and prints a syntax
   overview for the particular command.

The following subsections describe the available commands together with their arguments, if there are any.

schema-id
---------

Print a unique module set identifier that can be used, for example, as
the value of the *module-set-id* leaf in YANG library data.

digest
------

Print the schema digest in JSON format as a simplified specification
of the schema. It is intended to be used in constrained environments
such as web applications.

.. _dump-cmd:

dump
----

Dump the serialized (pickled) data model object to a file.

.. option:: <file>

   Name of the file.

.. _tree-cmd:

tree
----

Print the tree diagram of the complete data model as ASCII art.

.. option:: -n, --no_types

   Suppress data type information in the tree diagram.

validate
--------

Validate a JSON instance object against the complete data model or a
subschema.

An instance object that is to be validated against the subschema of an
action or RPC can be input and/or output payload of the action or RPC
enclosed in ``<modulename>:input`` or ``<modulename>:output``,
respectively. The subschema of a notification can be used for
validating notification payload.

Note that validation against a subschema may fail if the subschema or
the instance contain XPath or leafref references to configuration or
state data outside the selected subschema.

.. option:: <instance>

   The name of a file containing an instance object in JSON
   representation.

.. option:: -c <content_type>, --ctype <content_type>

   Content type of the instance object, should be one of

   * ``config`` – configuration data
   * ``state`` – operational state data
   * ``input`` – input data of an action of RPC operation
   * ``output`` – output data of an action of RPC operation
   * ``notification`` – notification data
   * ``rpc_action`` – combination of ``input`` and ``output``
   * ``nonconfig`` – everything except ``config``
   * ``all`` – all content types.

   If this option isn't specified, the content type is assumed to be
   identical to the root node of the schema or subschema against which
   the instance object is validated.

.. option:: -s <validation_scope>, --scope <validation_scope>

   Validation scope, should be one of

   * ``syntax`` – schema constraints (including **when**
     and **if-feature** conditions) and data types;
   * ``semantics`` – **must** constraints, uniqueness of list
     keys, **unique** constraints in lists, integrity of **leafref**
     and **instance-identifier** references;
   * ``all`` – all of the above.

   The default value is ``all``. See also :meth:`.InstanceNode.validate`.

Environment Variables
=====================

YANG_MODPATH
   A colon-separated list of directories that is used as the default module
   path, see the :option:`--path` option.

Exit Status
===========

+-------+---------------------------------------------+
| Value | Meaning                                     |
+=======+=============================================+
|   0   | No errors                                   |
+-------+---------------------------------------------+
|   1   | Problem with an argument                    |
+-------+---------------------------------------------+
|   2   | YANG library or data model problem          |
+-------+---------------------------------------------+
|   3   | Validation of the instance object failed    |
+-------+---------------------------------------------+
